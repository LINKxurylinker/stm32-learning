# 一、定时器：TIM2 是怎么变成一块"秒表"的

### 为什么需要它

滤波里有一句 `pitch += 角速度 × dt`。**角速度是"每秒转多少度"，乘上"过了多少秒"才是角度。** 这个 `dt` 必须是真实测量值，不能猜。

### STM32 定时器的本质（江科大原话：就是一个"一直在数的计数器"）

```
时钟 84MHz  →[预分频 PSC=84-1]→  1MHz  →[计数器 CNT 一直加]→ 每加 1 = 1 微秒
                                    ↑
                        自动重装 ARR=0xFFFFFFFF（数满 42 亿才回绕，约 71 分钟）
```

对应代码（**第 84 行 `timer_init`**）：

```c
t.TIM_Prescaler = 84 - 1;      /* ① 84MHz ÷ 84 = 1MHz，也就是"一格 = 1 微秒" */
t.TIM_Period    = 0xFFFFFFFF;  /* ② 数满才回绕，等于"一块不会停的秒表" */
TIM_Cmd(TIM2, ENABLE);         /* ③ 打开 */
```

读时间的函数只有一行（**第 98 行**）：

```c
static u32 us_now(void) { return TIM_GetCounter(TIM2); }
```

### 关键对比：为什么**不用**定时器中断？

| | 定时器中断（江科大常用） | **自由计数（我们用）** |
|---|---|---|
| 做法 | 每 1ms 进一次中断，中断里干活 | 不中断，主循环随时读 CNT 作差 |
| 好处 | 节拍绝对精确，与主循环无关 | 主循环想怎么慢就怎么慢，不影响计时 |
| 适合 | 严格周期性的任务（PWM、采样触发） | **只需要"知道现在几点"** 的场合 |

我们的主循环又要读 I2C（约 1ms）又要刷屏（约 3~5ms），用中断反而别扭；而滤波只需要"两次采样之间隔了多久"——读一下计数器就够了。

### 一个必须知道的技巧：无符号作差

```c
dt = (now - last) * 1e-6f;    /* last 是上次的时间戳 */
```

`now` 和 `last` 都是 32 位无符号数，**即使计数器绕回 0，减法结果依然正确**（模 2³² 运算）。
但如果你写成 `if (now >= last + 50000)`，绕回那一瞬间就会**永远不再触发**——这是嵌入式最经典的坑之一。

**一句话总结**：定时器 = 由时钟驱动的计数器；配好 PSC 得到"一格多少微秒"，配好 ARR 决定"数到多少回绕"，然后你就能随时"看表"。

# 二、主循环：一个没有操作系统的"多任务"

### 需求清单

| 任务 | 要多久一次 | 为什么 |
|---|---|---|
| 读传感器 + 滤波 | **100 Hz** | 滤波效果依赖采样均匀，快一点跟手 |
| 刷新屏幕 | **20 Hz** | 人眼够用；刷屏最贵 |
| 更新参数文字 | **10 Hz** | 数字跳太快反而看不清 |
| 按键 | 随时 | 用户手一按就得响应 |

### 做法：一圈一圈跑，用时间戳决定这圈干哪些事

```c
for (;;)
{
    imu_read(...);                       /* ★ 每圈必做 → 这就是 100Hz 的来源 */
    now = us_now();                      /* 这一圈的"现在" */

    if ((u32)(now - t_text) >= 100000u) { t_text = now; /* 刷文字, 10Hz */ }
    if ((u32)(now - t_fps)  >= 1000000u){ t_fps  = now; /* 每秒统计帧率 */ }

    if (KEY_Scan(0) == KEY0_PRESS) { ... }   /* 随时响应 */
    delay_ms(5);                             /* 补足一圈约 6~10ms */
}
```

### 两个设计要点

1. **采样"每圈必做"，显示"有条件"**：采样必须均匀（`dt` 稳定，积分才准）；显示只要够用（20Hz 人眼就是流畅的）。
2. **末尾 `delay_ms(5)` 只是"补一点"，不是"精确节拍"**：因为一圈里读 I2C、刷屏花的时间不固定。**但没有关系**——`dt` 是实测的，滤波自动适应。这就是"用真实时间而不是假设时间"的好处。

**一句话总结**：主循环 + 时间戳比较 = 最朴素的"软定时多任务"，嵌入式里比 RTOS 更常用。

# 三、MPU6050：怎么把"重力"变成两个字节

### 1. 芯片里有两个传感器，共用一套轴

| | 测什么 | 单位 | 强项 | 弱项 |
|---|---|---|---|---|
| 加速度计 | 重力方向 | g | 长期准 | 短期抖 |
| 陀螺仪 | 旋转角速度 | °/s | 短期准 | 积分会漂 |

**它们做在同一块硅片上、共用 Sx/Sy/Sz 三根轴**——这就是"改了加速度的轴，陀螺的轴必须跟着改"的原因（你昨天踩的那个坑）。

### 2. 上电第一件事：唤醒它

`0x6B` 寄存器上电默认是**睡眠**状态。不唤醒，读回来全是 0：

```c
写 0x6B = 0x80   /* 软复位 */  → 延时 100ms
写 0x6B = 0x00   /* 唤醒   */
读 0x75          /* 应该返回 0x68，确认芯片在 */
```

### 3. 一次读回全部数据（**第 132 行 `imu_read`**）

起点选 `0x3B`，一次读 **14 字节**：

| 字节 | 内容 | 换算 |
|---|---|---|
| 0~5 | 加速度 X/Y/Z | 原始值 ÷ **16384** = g（±2g 量程）|
| 6~7 | 温度 | ÷340 + 36.53 = ℃ |
| 8~13 | 角速度 X/Y/Z | 原始值 ÷ **65.5** = °/s（±500dps 量程）|

**为什么一次读 14 个字节而不是分三次读**：I2C 每次事务都要"起始→地址→寄存器→再起始→读→停止"，一次读完顶三次，省 2/3 的通信时间。

### 4. 拼字节为什么写那么绕

```c
a[0] = (short)(((u16)buf[0] << 8) | buf[1]);
```

芯片是**大端**输出（高字节在前）。先把 `buf[0]` 转成无符号再左移 8 位，或上低位，最后强转成 `short`——这样**负数才是对的**（直接拿 `char` 左移会被符号位捣乱）。

### 5. 零偏：陀螺静止时不为 0

数据手册允许静止输出有偏差，实际板子上常见几十到上千 LSB。**不扣掉，积分一秒钟就漂好几度**：

```c
for (i = 0; i < 100; i++) { 读; bx += g[0]; ... delay_ms(10); }   /* 第657行, 采 1 秒 */
bx /= n;  ...   然后每次: gx = (g[0] - bx) / 65.5f;
```

**为什么加速度不用标零偏**：它给的是绝对角度，传感器的零偏会体现在角度值上；而"什么算水平"是**用户说的算**——按 KEY0 归零就把它补掉了。

**一句话总结**：MPU6050 = 两个传感器 + 一套轴 + 一堆寄存器；用之前先唤醒、读回 14 字节、除掉系数、扣掉零偏。

# 四、角度：从 (ax, ay, az) 到 pitch / roll

### 1. 物理图像

静止时，加速度计感受到的是**支撑力**（和重力等大反向），所以读数是一个**长度 1g、方向指着"上"的矢量**。

* 板子平放 → 这个矢量在板子坐标系里是 `(0, 0, +1g)`
* 板子倾斜 θ → 这个矢量在板子坐标系里**转了同样的 θ**

### 2. 单轴推导（抬远端）

抬高远端 θ 角后，矢量分解成两部分：

```
指向"远端方向"的分量 = sinθ   →  这就是 fax（对我们这块板子）
垂直于板面的分量     = cosθ   →  这就是 faz
```

于是

```
θ = atan2(sinθ, cosθ) = atan2(fax, faz)
```

**代码（第 691~692 行）就是这两句**：

```c
float ap = atan2f( fax, faz) * 57.29578f;   /* 抬远端 θ → ap = +θ */
float ar = atan2f(-fay, faz) * 57.29578f;   /* 抬右端 θ → fay 为负, 取反后 ar = +θ */
```

（`57.29578 = 180/π`，因为 `atan2f` 返回**弧度**。）

### 3. 为什么用 `atan2` 而不是 `asin`

| | `asin(x)` | `atan2(y, x)` |
|---|---|---|
| 有效范围 | 只有 ±90° | 全角度，自带象限判断 |
| 用到的信息 | 只用一根轴 | **同时用两根轴的比例** |
| 分母接近 0 时 | 噪声被放大到爆炸 | 依然稳定 |

而且用 `atan2` 有个副作用是**好事**：

> **量程系数会自动约掉**——`atan2(ax/16384, az/16384)` 和 `atan2(ax, az)` 完全一样。

顺便**纠正我之前一句话**：我说过"改了加速度量程忘了改系数，角度会成比例错"——**那句对 atan2 算出来的角度是错的**（比例约掉了，角度不受影响），受影响的是"多少 g"这类读数。**真正会被量程系数坑到的是陀螺那一侧**，因为它是 `角速度 × dt` 参与积分的。

### 4. 符号约定的来源

我们的要求是"**哪边高，气泡往哪边跑**"（真实水平仪就是这样）：

* 抬**远端** → 我们要 `PITCH > 0` → 而抬远端让 `fax > 0` → 直接用 `+fax` ✅
* 抬**右端** → 我们要 `ROLL > 0` → 而抬右端让 `fay < 0` → 所以要 `-fay` ✅

**注意**：这两个符号和"传感器在板子上怎么装"强相关。装法一变，公式就得变——这就是生产版要做**轴向自检向导**的原因。

**一句话总结**：倾斜时重力矢量在板子坐标系里跟着转；**"某根轴的分量 ÷ 垂直分量"的反正切就是倾角**，符号按"哪边高为正"定。

# 五、互补滤波：让两个"各有毛病"的传感器互相纠正

| 来源 | 测法 | 毛病 |
|---|---|---|
| 加速度计 | `ap = atan2(轴, az)` | **抖**（一碰就跳）|
| 陀螺仪 | `pitch += 角速度 × dt` | **漂**（零偏和噪声积分累积）|

一个长期准、一个短期准 → **按比例采信**：

```c
pitch = 0.98f * (pitch - gy * dt) + 0.02f * ap;
/*      └── 97%: 上一刻角度 + 这一段的角速度积分 ──┘  └ 2%: 重力测的绝对角度 ┘ */
```

### 三个参数的意义

| 东西 | 作用 | 调大的后果 |
|---|---|---|
| `dt` | 把"每秒多少度"变成"这一段转了多少度" | 必须实测，写死会在主循环变慢时出错 |
| `K = 0.98` | 采信陀螺的比例 | K 越大越平滑但越"拖"；K 越小越跟手但越抖 |
| `1-K = 0.02` | 重力纠偏的力度 | 决定"多久把漂移拉回来一次"：`τ ≈ dt/(1-K) ≈ 0.5 秒` |

### 两个容易忽略的保护

```c
if (dt > 0.05f)  { dt = 0.05f; }    /* 断点调试/卡顿后, 别让积分一次冲飞 */
if (dt < 0.001f) { dt = 0.001f; }   /* 也别小到除出问题 */
if (first) { pitch = ap; roll = ar; first = 0; }   /* 第一次直接用重力值初始化, 不从 0 慢慢爬 */
```

**一句话总结**：**陀螺管短期、重力管长期，加权平均就得到一个"又稳又不漂"的角度。**

# 六、UI：一个像素是怎么画到屏上的

### 1. 屏的模型：显存 + 窗口

```
设窗口(0x2A 列, 0x2B 行) → 写颜色(0x2C) → 自动往右推进 → 写满一行自动换行
```

于是：

| 想画 | 最省事的做法 | 代价 |
|---|---|---|
| 一个点 | 设 1×1 窗口 + 写 1 个颜色 | 慢（每次设窗口要发好几条命令）|
| 一条横线 | 设 1×N 窗口 + 连写 N 个颜色 | 快 |
| 一个实心圆 | **每一行算一次半宽，画一行** | 41 行 `LCD_Fill` 画完半径 20 的圆 |

实心圆的核心公式（**第 626 行 `fill_circle`**）：

```c
for (dy = -r; dy <= r; dy++) {
    dx = (int)sqrtf((float)(r * r - dy * dy));       /* 勾股定理: 这一行的半宽 */
    LCD_Fill(cx - dx, cy + dy, cx + dx, cy + dy, col);
}
```

### 2. 靶心三层圆的含义

| 圆 | 半径 | 代表 |
|---|---|---|
| 外圈（灰）| 72 px | **±2.0°**（满量程）|
| 靶环（黄）| 36 px | ±1.0° |
| 靶心（绿）| 14 px | ±0.4° |

所以"外圈到圆心的距离"就是倾角的刻度尺：**1 度 = 36 像素**（`k = LV_ROUT / 2`）。

### 3. 角度 → 气泡坐标（**第 713~720 行**）

```c
k  = LV_ROUT / 2.0f;          /* 36 像素/度 */
dx = (int)(roll  * k);        /* 向右为正 */
dy = (int)(-pitch * k);       /* ★ 取负: 屏幕 y 轴向下, 而"抬起"是向上 */
lim = LV_ROUT - LV_BUBR - 2;  /* 气泡中心能跑到的最远半径 */
if (mag * k > lim) { float f = lim / (mag * k); dx *= f; dy *= f; }   /* 圆形钳位 */
```

**钳位为什么用"按比例缩小"而不是"截断到边界"**：按比例缩小保持了运动方向不变，气泡会沿着**圆周**滑动；直接截断会让它贴着方框四个角跑，看着很怪。

### 4. 刷新分两档（这是"不闪"的关键）

| 内容 | 频率 | 做法 | 耗时 |
|---|---|---|---|
| 圆盘（三个环 + 气泡）| 每帧 | 擦圆盘方框 → 重画三环 → 画气泡 | 约 3~5 ms |
| 下面三行参数文字 | 10 Hz | 先 `LCD_Fill` 清该行 → 再 `LCD_ShowString` | 几 ms |

两个细节：

* **擦的是"圆盘所在的方框"（150×150），不是整屏**：整屏 76800 像素，圆盘区只有 22500；
* **清行再写字**：否则新字符串比旧的短时，末尾会留下残字。

**一句话总结**：先想"这块区域要变成什么样"，再挑**最少的窗口设置 + 最多的连续写**去实现它。

# 一、I2C 到底解决什么问题

你要在板子上挂很多芯片（MPU6050、EEPROM、OLED……）。如果每个都用一堆线（片选、8 根数据、读写……），引脚根本不够。

I2C 的方案是**只用两根线**：

| 线 | 名字 | 谁驱动 |
|---|---|---|
| SCL | 时钟线 | **只有主机**产生节拍 |
| SDA | 数据线 | 主从**共用**，谁说话谁驱动 |

规则是**一主多从**：主机发节拍、点名（发地址），被点到的从机才应答。

打个比方：**SCL 是老师敲的节拍器，SDA 是学生嘴里说的话。**
关键规矩只有一条：**老师看过来的时候（SCL 高电平），你不能改口型；只能趁节拍间隙（SCL 低电平）换词。**
这条规矩就是整个 I2C 时序的地基。

---

# 二、硬件前提：为什么数据线要"开漏 + 上拉"

先想一个问题：**SDA 是大家共用的一根线，如果一个设备想输出高、另一个想输出低，会怎样？**
→ 推挽输出的高就是直接接到电源、低就是直接接到地，**两个一起 = 电源短路**，管子烧掉。

所以 I2C 规定 SDA 用**开漏输出**：

* **只能主动拉低，不能主动拉高**；
* 高电平靠一根**上拉电阻**（没任何人拉低 = 被电阻拉成高）。

这样一来就变成了"**线与**"：**只要有一个设备拉低，线就是低**。谁也没意见时才是高。这正好满足"多人共用一根线"和"应答"的需求。

## 这份例程的变通做法（重点看这里）

打开 `APP\iic\iic.c` 第 10 行 `IIC_Init`：

```c
GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_OUT; //普通输出
GPIO_InitStructure.GPIO_OType = GPIO_OType_PP; //★ 推挽, 不是开漏
GPIO_InitStructure.GPIO_PuPd  = GPIO_PuPd_UP;  //★ 上拉
```

它是**推挽 + 上拉**，不是开漏。那怎么做到"放开线"？靠**切换引脚方向**：

| 想干什么 | 怎么做 | 代码 |
|---|---|---|
| 说"0" | 配成输出，输出低 | `SDA_OUT()` 然后 `IIC_SDA=0` |
| 说"1" / 放开线 | **配成输入**，靠内部上拉把它拉高 | `SDA_IN()`（iic.c:51） |
| 读线 | 配成输入再读 | `READ_SDA`（iic.h:13，位带读 PB9）|

这就是"**伪开漏**"：用"输入模式 = 高阻"来模拟开漏的"不驱动"。

> 更正规的写法是把 SDA 配成 `GPIO_OType_OD`（真开漏），就不用每次切方向了。这份例程用切方向的办法，胜在直观——**你能从代码里看出每一步到底谁在驱动这根线**，学时序反而更清楚。

# 三、五条基本时序（背下来就够）

### ① 空闲状态
SCL = 1，SDA = 1。（两根线都被上拉拉高）

### ② 起始条件 START：**SCL 高的时候，SDA 由高变低**

```
SCL  ‾‾‾‾‾‾‾‾‾\________
SDA  ‾‾‾‾‾‾\___________
            ↑ 这一瞬间 SCL 还是高, SDA 掉了 → 从机: "要开始了!"
```

### ③ 数据位：**SCL 低时改数据，SCL 高时数据必须稳定**

```
SCL  ‾‾‾\______/‾‾‾‾\______/‾‾‾
SDA  ‾‾‾‾‾X‾‾‾‾‾‾‾‾‾X‾‾‾‾‾‾‾
          ↑ 低: 允许改数据    ↑ 高: 从机把它读走(此刻必须稳)
```

每个字节 **8 位，高位先发（MSB first）**。

### ④ 应答 ACK：第 9 个时钟周期

主机发完 8 位后**放开 SDA**（切成输入）；从机如果收到了，就把 SDA 拉低 = **ACK**；不拉 = **NACK**。

```
第 8 位  第 9 个时钟
SCL  ___/‾‾‾\___/‾‾‾\___
SDA  ──── 主机放开 ────
         从机拉低 = ACK (读到 0)
         从机不动 = NACK (读到 1)
```

### ⑤ 停止条件 STOP：**SCL 高的时候，SDA 由低变高**

```
SCL  ________/‾‾‾‾‾‾‾‾
SDA  ________/‾‾‾‾‾‾‾‾
            ↑ SCL 高时 SDA 升上去 → 从机: "结束了"
```

**这五条就是全部。** 剩下的都是它们的排列组合。

# 四、一次完整的"读 MPU6050 的 14 字节"长什么样

看 `APP\mpu6050\mpu6050.c` 第 161 行 `MPU6050_Read_Len`，它对应的时序是：

| 步 | 线上发生的事 | 代码 |
|---|---|---|
| 1 | **起始** | `IIC_Start();`（163）|
| 2 | 发 `0x68<<1 \| 0` = **0xD0**（点名 + 我要写） | `IIC_Send_Byte((addr<<1)\|0)`（164）|
| 3 | 等 ACK（从机应答）| `if(IIC_Wait_Ack())`（165）|
| 4 | 发寄存器地址 **0x3B**（告诉它从哪儿开始读）| `IIC_Send_Byte(reg)`（170）|
| 5 | 等 ACK | （171）|
| 6 | **再发一次起始**（这叫"重复起始"，注意中间**没有**停止）| `IIC_Start();`（172）|
| 7 | 发 `0x68<<1 \| 1` = **0xD1**（点名 + 我要读）| （173）|
| 8 | 等 ACK | （174）|
| 9 | 连读 14 个字节：**前 13 个回 ACK，最后一个回 NACK** | 175~181 |
| 10 | **停止** | `IIC_Stop();`（182）|

### 两个"为什么"

**为什么第 6 步要"重复起始"而不是"停止再起始"？**
因为从机内部有一个"当前读到哪个寄存器"的指针。**一旦收到停止条件，很多从机（包括 MPU6050）会把指针复位**，你就读不到 0x3B 开始的数据了。用重复起始（START 紧跟 START，中间没有 STOP）可以把"我要读这个寄存器"这个上下文保持住。

**为什么最后一个字节要回 NACK？**
ACK 的意思是"我还要下一个字节"。读最后一个的时候，主机必须**主动说 NACK**（把 SDA 放开让它是高），从机才知道"他读完了，我松手"——否则从机会继续往总线上推数据，和主机的停止条件打架。

代码里就是这一句（177~178）：

```c
if(len==1) *buf=IIC_Read_Byte(0);   /* 最后一个: 发 NACK */
else       *buf=IIC_Read_Byte(1);   /* 其它:    发 ACK  */
```

# 五、逐行读 `iic.c` 的 10 个函数

### 1. `IIC_Init`（第 10 行）—— 配置两根线
GPIOB 时钟 → PB8/PB9 配成推挽输出 + 上拉 → 先把两根线都拉高（**空闲状态**）。

### 2. `SDA_OUT`（32）/ `SDA_IN`（51）—— 切换 SDA 的角色
就是上面说的"伪开漏"。注意 `SDA_IN` 里也配了**上拉**，这样一放开线，它自然变高。

### 3. `IIC_Start`（68）—— 起始条件
```c
SDA_OUT();
IIC_SDA=1;  IIC_SCL=1;  delay_us(5);   /* 先确保两根线都是高(空闲) */
IIC_SDA=0;              delay_us(6);   /* ★ SCL 高时 SDA 下降 = 起始 */
IIC_SCL=0;                             /* 拉低 SCL, 准备发数据(钳住总线) */
```

### 4. `IIC_Stop`（85）—— 停止条件
```c
SDA_OUT();
IIC_SCL=0;  IIC_SDA=0;  delay_us(2);
IIC_SCL=1;              delay_us(6);   /* 先把 SCL 拉高 */
IIC_SDA=1;              delay_us(6);   /* ★ SCL 高时 SDA 上升 = 停止 */
```

### 5. `IIC_Send_Byte`（164）—— 发一个字节（**MSB 先发**）
```c
SDA_OUT();
IIC_SCL=0;                             /* 低电平期间准备改数据 */
for(t=0; t<8; t++) {
    if(txd & 0x80) IIC_SDA=1; else IIC_SDA=0;   /* 摆好这一位 */
    txd <<= 1;                                  /* 把下一位挪到最高位 */
    delay_us(2);
    IIC_SCL=1;   delay_us(2);          /* ★ 拉高, 从机读走 */
    IIC_SCL=0;   delay_us(2);          /* 拉低, 准备下一位 */
}
```
**这三句 `delay_us` 就是整个总线的速度来源**（下面第六节算给你看）。

### 6. `IIC_Wait_Ack`（103）—— 收应答（含超时）
```c
SDA_IN();                              /* ★ 放开 SDA, 让从机说话 */
IIC_SDA=1;  delay_us(1);
IIC_SCL=1;  delay_us(1);               /* 第 9 个时钟 */
while(READ_SDA) {                      /* 读到 0 = 有人拉低 = ACK */
    tempTime++;
    if(tempTime>250) { IIC_Stop(); return 1; }   /* 超时: 没人应答 */
}
IIC_SCL=0;
return 0;
```
**注意一个细节**：`while` 循环里**没有延时**，所以"250 次超时"其实只有**几十微秒**——比你以为的短得多。这是这份代码的一个隐患（下面第七节讲）。

### 7. `IIC_Ack`（130）/ `IIC_NAck`（147）—— 主机应答从机
读数据时，主机在第 9 个时钟把 SDA 拉低（ACK）或保持高（NACK）：
```c
IIC_SCL=0;  SDA_OUT();
IIC_SDA = 0;   /* ACK: 拉低 */      /* 147 行这里是 IIC_SDA=1 → NACK */
delay_us(2);  IIC_SCL=1;  delay_us(5);  IIC_SCL=0;
```

### 8. `IIC_Read_Byte`（190）—— 读一个字节
```c
SDA_IN();                              /* 主机放开, 由从机驱动 */
for(i=0;i<8;i++) {
    IIC_SCL=0;  delay_us(2);
    IIC_SCL=1;                         /* ★ 拉高, 此刻线上就是从机的数据 */
    receive <<= 1;
    if(READ_SDA) receive++;            /* 读到 1 就补上这一位 */
    delay_us(1);
}
if(!ack) IIC_NAck(); else IIC_Ack();   /* 读完要回一个应答 */
return receive;
```
对比一下 `Send_Byte` 和 `Read_Byte`：**写的时候是"先摆数据再抬 SCL"，读的时候是"先抬 SCL 再取数据"**——方向不同，但规矩是同一条：**SCL 高电平期间，线上的数据是有效的。**

`IIC_Send_Byte` 里每一位要 `2+2+2 = 6µs`，加上位带写引脚的几条指令，**一位大约 6~7µs**：

* 一个字节 + ACK ≈ 9 位 ≈ **60µs**

| 方式 | 一位耗时 | 读 14 字节 |

# 七、四个必须知道的坑

### 坑 1：地址要左移一位
MPU6050 的 7 位地址是 `0x68`。但线上传的是 **8 位**：`0x68<<1 | 读写位`。

| 用途 | 线上发的字节 |
|---|---|
| 写 | `0xD0` |
| 读 | `0xD1` |

**新手最常犯的错就是直接发 `0x68`**，结果永远等不到 ACK（因为 0x68 对应的其实是另一个设备的地址）。

### 坑 2：`IIC_Wait_Ack` 的超时短得可怜
`while(READ_SDA)` 里没有延时，250 次大概只有 **20~30µs**。也就是说从机必须在 20µs 内拉低 SDA。
正常从机 1µs 内就拉了，够用；但如果总线电容大、上拉电阻大（波形上升沿很慢），就可能**误判成"没人应答"**。改进办法：循环里加个 `delay_us(1)`，超时时间变成 250µs。

### 坑 3：`MPU6050_Read_Len` 里有两处没检查返回值
```c
IIC_Send_Byte(reg);   // 170 行
IIC_Wait_Ack();       // 171 行 ← 返回值丢了! 从机没应答也会继续往下读
```
如果从机在这一步掉线，程序会读到一堆 0xFF（看起来像"数据全是 4095"），而不是报错。**这是可以改进的地方**：把返回值判断上，失败就 `IIC_Stop()` 并返回 1。

### 坑 4：SDA/SCL 接反或没上拉
现象是"时好时坏"、"读到的 ID 偶尔对偶尔错"。这也是为什么**动 `delay_us` 的数值能测出时序余量**（见下面的实验）。

```c
IIC_Send_Byte((MPU6050_ADDR<<1)|0);             // 点名 + 我要写 (0xD0)
if(IIC_Wait_Ack()) { IIC_Stop(); return 1; }    // ★ 没人应答 → 立刻收工返回错误
IIC_Send_Byte(reg);  IIC_Wait_Ack();            // 告诉它"写哪个寄存器"
IIC_Send_Byte(data);                            // 把数据放上去
if(IIC_Wait_Ack()) { IIC_Stop(); return 1; }    // ★ 再确认它收下了
IIC_Stop();  return 0;                          // 结束
```

**这就是"写寄存器"这四个字的全部含义**：起始 → 点名 → 说地址 → 给数据 → 停止。
注意它两次检查 ACK，**并且每次失败都先 `IIC_Stop()` 再返回**——这是好习惯：不能把总线丢在半路（否则从机会一直等着，下次通信就乱了）。

## 2. `MPU6050_Read_Byte`（第 213 行）—— 读一个寄存器

```c
IIC_Start();
IIC_Send_Byte((MPU6050_ADDR<<1)|0);   // ① 先用"写"的方式点名
IIC_Wait_Ack();
IIC_Send_Byte(reg);                   // ② 告诉它"我要读哪个寄存器"
IIC_Wait_Ack();
IIC_Start();                          // ③ ★ 重复起始(中间没有停止!)
IIC_Send_Byte((MPU6050_ADDR<<1)|1);   // ④ 再点名 + 我要读 (0xD1)
IIC_Wait_Ack();
res = IIC_Read_Byte(0);               // ⑤ 读一个字节, 回 NACK(因为只读一个)
IIC_Stop();
return res;
```

**和 `Write_Byte` 对比着看**，多出来的就是第 ③④ 步：

* 地址发了**两次**——第一次"写"是为了设置从机内部的寄存器指针，第二次"读"才是真读；
* 读最后要回 `IIC_Read_Byte(0)`，也就是 **NACK**："我只要一个，别给了"。

## 3. `MPU6050_Read_Len`（第 161 行）—— 连续读（我们的主力）

结构和 `Read_Byte` 一样，只是把"读一个"换成"循环读 len 个"：

```c
while(len) {
    if(len==1) *buf = IIC_Read_Byte(0);   // 最后一个 → NACK
    else       *buf = IIC_Read_Byte(1);   // 其它    → ACK(继续给)
    len--;  buf++;
}
```

**为什么强烈建议用它而不是分别调 `Get_Accelerometer` + `Get_Gyroscope` + `Get_Temperature`**：
这三个函数各自发起一次完整事务（起始→地址→寄存器→重复起始→读→停止），也就是**3 次点名**；而 `Read_Len` 一次把 0x3B 起的 14 个字节全搬回来，**1 次顶 3 次**。在 100Hz 采样下，这直接省掉 2/3 的 I2C 时间。

## 4. `MPU6050_Write_Len`（第 130 行）—— 连续写（我们没用）

就是 `Write_Byte` 里的"发数据"部分变成循环，**每发一个字节都等一次 ACK**。用它需要连续写多个寄存器时很方便（比如批量初始化）。我们不用它，是因为所有配置都是单个寄存器写。

# 四、①配置层：5 个函数

## 1. `MPU6050_Init`（第 10 行）—— 上电八步曲

| 步 | 代码 | 干什么 | 为什么 |
|---|---|---|---|
| 1 | `IIC_Init()` | 配好 PB8/PB9 | 后面所有通信的前提 |
| 2 | 写 `0x6B = 0x80` | **软复位** | bit7 = DEVICE_RESET |
| 3 | `delay_ms(100)` | **等它重启** | ★ 复位是异步的，芯片正在重启时你发命令它不理会（会 NACK）|
| 4 | 写 `0x6B = 0x00` | **唤醒** | bit6 = SLEEP 清零（上电默认是睡着的！）|
| 5 | `Set_Gyro_Fsr(3)` | 陀螺 ±2000dps | 例程的默认值 |
| 6 | `Set_Accel_Fsr(0)` | 加速度 ±2g | |
| 7 | `Set_Rate(50)` | 采样率 50Hz | 注意副作用，见下面第 4 点 |
| 8 | 关中断/关主模式/关 FIFO/INT 引脚低有效 | 用不到的功能全关掉 | 干净 |
| 9 | `res = Read_Byte(0x75)` | **读器件 ID 校验** | `if(res==MPU6050_ADDR)` 才算成功，否则 `return 1` |
| 10 | 写 `0x6B=0x01`、`0x6B… 0x6C=0x00` | 时钟源选 PLL X 轴陀螺；六轴都工作 | 用陀螺的 PLL 当系统时钟比内部 RC 准得多 |

**两点值得注意**：

* **第 9 步的写法有点"抄近路"**：`MPU6050_ADDR` 是 **0x68**（器件地址），而 `0x75` 寄存器返回的 WHO_AM_I 恰好也是 **0x68**，所以这个比较成立。但语义上它比的是"地址常量"而不是"ID 常量"——**能跑，但容易让人误会**，写成 `if(res == 0x68)` 会更清楚。
* **第 25 行有一句 `printf("res=0x%x\r\n",res);`** —— 这是作者留的调试打印。**在工程里留一句关键的自检打印是好习惯**，我们的学习版跑起来就会在串口看到 `res=0x68`。

## 2. `Set_Gyro_Fsr`（38）/ `Set_Accel_Fsr`（46）—— 只干一件事

```c
return MPU6050_Write_Byte(MPU6050_GYRO_CFG_REG, fsr<<3);
```

**为什么左移 3 位**：量程寄存器（0x1B / 0x1C）里，量程占 **bit3~bit4**，低 3 位是自检位。所以 `fsr`（0~3）要挪到 bit3 的位置：

| fsr | 写入值 | 加速度 | 陀螺 |
|---|---|---|---|
| 0 | 0x00 | ±2g | ±250 dps |
| 1 | 0x08 | ±4g | ±500 dps |
| 2 | 0x10 | ±8g | ±1000 dps |
| 3 | 0x18 | ±16g | ±2000 dps |

**记住这张表和它的换算系数**（`16384/8192/4096/2048` 和 `131/65.5/32.8/16.4`），改了量程就得改系数。

## 3. `Set_LPF`（54）—— 一个"查表翻译"函数

它把"你想要的带宽（Hz）"翻译成"寄存器里的档位（0~6）"：

```c
if(lpf>=188) data=1;        /* → 陀螺带宽 188Hz */
else if(lpf>=98)  data=2;   /* → 98Hz  */
else if(lpf>=42)  data=3;   /* → 42Hz  */
else if(lpf>=20)  data=4;   /* → 20Hz  */
else if(lpf>=10)  data=5;   /* → 10Hz  */
else              data=6;   /* → 5Hz   */
```

**这张映射表其实对应数据手册里"陀螺带宽"那一列**（加速度那列会略有不同）。档位越大越平滑，但延迟越大：

| 档位 | 加速度带宽 | 陀螺带宽 | 延迟 |
|---|---|---|---|
| 3 | 44 Hz | 42 Hz | ≈4.9 ms |
| 4 | 21 Hz | 20 Hz | ≈8.5 ms |
| 5 | 10 Hz | 10 Hz | ≈13.8 ms |

## 4. `Set_Rate`（69）—— **藏着一个副作用，这是这个文件最值得注意的地方**

```c
data = 1000/rate - 1;                       /* 分频值 */
MPU6050_Write_Byte(MPU6050_SAMPLE_RATE_REG, data);
return MPU6050_Set_LPF(rate/2);             /* ★★ 顺手把 LPF 改成采样率的一半! */
```

也就是说——**`Set_Rate()` 会偷偷调用 `Set_LPF()` 覆盖你之前的设置**。

回头看你学习版的 `imu_init()`：

```c
MPU6050_Set_LPF(20);     /* 我注释写的是"芯片内部低通 20Hz" —— 这句其实白写了! */
MPU6050_Set_Rate(100);   /* 内部会执行 Set_LPF(50) → 50>=42 → 档位 3 → 实际带宽 42Hz */
```

所以**芯片里最终的 DLPF 档位是 3（42Hz），不是我注释里写的 20Hz**。这是我注释没写准的地方，正好当作一个教训：

> **看例程时一定要留意"函数内部还会调用别的函数"**——这种隐藏副作用是嵌入式代码里最常见的坑之一。

（顺带：`Set_Rate(100)` 里 `data = 1000/100-1 = 9`，所以采样率 = 1000/(1+9) = **100Hz** ✓ 这就是它注释里"假定 Fs=1KHz"的意思。）

# 五、③便捷读取层：3 个 `Get_*`（我们为什么不用）

| 函数 | 行号 | 干什么 | 我们为什么没用 |
|---|---|---|---|
| `Get_Temperature` | 81 | 读 2 字节温度，返回 **×100 的整数**（避免浮点）| 我们的 `Read_Len` 已经把温度一起读回来了 |
| `Get_Gyroscope` | 95 | 读 6 字节角速度原始值 | 同上 |
| `Get_Accelerometer` | 111 | 读 6 字节加速度原始值 | 同上 |

它们的返回值都是**原始整数**（没做换算），换算还得你自己写：
```c
加速度(g) = 原始值 / 16384.0f;      /* ±2g */
角速度(°/s) = 原始值 / 65.5f;       /* ±500dps */
温度(℃)   = 原始值 / 340.0f + 36.53f;
```

**为什么"能一次读完就别分三次"**：I2C 每次事务都要"点名 + 报地址 + 反复起始"，一次读 14 字节只花一次点名的开销。这就是我们宁可自己写 `imu_read()` 的原因——**不是例程错，是需求不同**。

顺便记住命名规律：`..._XOUTH_REG` = "X 轴输出的**高字节**寄存器"。因为数据是 16 位、分两个寄存器存（高字节在前），所以从 `ACCEL_XOUTH_REG`（0x3B）开始连读 14 个字节，正好是：

```
0x3B~0x40 加速度 XYZ (6)  →  0x41~0x42 温度 (2)  →  0x43~0x48 角速度 XYZ (6)
```
