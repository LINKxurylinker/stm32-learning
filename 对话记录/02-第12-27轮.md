# 一、"单片机的库"到底指什么

你这个工程里其实有 **4 层**，从上到下：

```
第4层  你的业务代码        User\main.c、APP\level\level.c、ui.c          ← 你以后主要改这里
第3层  外设驱动（例程）     APP\iic、APP\mpu6050、APP\tftlcd、APP\key、APP\led、
                          Public\SysTick.c、usart.c、system.h(位带宏)     ← 正点原子/56dz 写的
第2层  ST 标准外设库 ★      Libraries\STM32F4xx_StdPeriph_Driver\inc|src\*.c/.h  ← "库"就是它
第1层  CMSIS 内核+启动层    Libraries\CMSIS\ startup_stm32f40_41xxx.s / system_stm32f4xx.c / core_cm4.h
       └ 编译器的器件头文件  User\stm32f4xx.h（寄存器结构体、外设基址、位定义）
```

**第 2 层就是"库"**：ST 把每个外设的寄存器操作包装成函数，
比如 `GPIO_Init()`、`RCC_AHB1PeriphClockCmd()`、`FSMC_NORSRAMInit()`、`USART_Init()`、`TIM_TimeBaseInit()`。

**第 1 层里的 `User\stm32f4xx.h` 才是"寄存器的真身"**：它用结构体把 GPIOA、USART1 这些外设的寄存器"排好队"，所以库函数内部最后都是在给这些结构体的字段赋值。

## 库函数的固定套路：三段式

打开 `APP\led\led.c` 第 9 行 `LED_Init()`，就是这个套路：

```c
RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOF, ENABLE);  // ① 先开这个外设的时钟
GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_9;            // ② 往结构体里填参数
GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_OUT;         //    模式：输出
GPIO_InitStructure.GPIO_OType = GPIO_OType_PP;         //    类型：推挽
GPIO_InitStructure.GPIO_Speed = GPIO_Speed_100MHz;     //    速度
GPIO_InitStructure.GPIO_PuPd  = GPIO_PuPd_UP;          //    上下拉
GPIO_Init(GPIOF, &GPIO_InitStructure);                 // ③ 把结构体交给库
```

三个要点：

1. **为什么第一步必须开时钟**：STM32 的外设时钟默认是关的（省电），不开时钟你后面写多少寄存器都无效——这是新手最常见的"代码没错但没反应"。
2. **那些 `GPIO_Mode_OUT` 能填什么**：全在 `Libraries\STM32F4xx_StdPeriph_Driver\inc\stm32f4xx_gpio.h` 里，是一串 `#define` 的枚举值。**看某个库函数怎么用，就是打开它的 .h**，参数含义、取值范围、返回值都写在上面（ST 的 .h 顶部通常还有"How to use this driver"的步骤说明）。
3. **库函数内部就是写寄存器**：你在 `GPIO_Init` 上按 **F12** 跳进去，会看到它在算 `GPIOx->MODER / OTYPER / OSPEEDR / PUPDR` 的位——这就是"库"和"寄存器"的桥。

## 一个"裁剪开关"要知道

`User\stm32f4xx_conf.h` 决定哪些外设头文件参与编译。我看过了，它是这么写的：

```c
#include "stm32f4xx_gpio.h"     // 34~52 行：所有系列都包含的基本外设
...
#if defined (STM32F40_41xxx)    // 79 行：我们是 F407，属于这一组
#include "stm32f4xx_cryp.h"
...
#include "stm32f4xx_fsmc.h"     // ★ 86 行：FSMC 只有这组才包含 —— LCD 能驱动就靠它
#endif
```

所以你在工程里 `#include "stm32f4xx_fsmc.h"` 能用，是因为宏 `STM32F40_41xxx`（在 `Options for Target → C/C++ → Define` 里定义）走了这个分支。

## 顺便解释工作区里另一个工程

| | 直接写寄存器 | **标准外设库（本工程）** | HAL / CubeMX（`LINKf407` 那个） |
|---|---|---|---|
| 代码量 | 最小 | 中 | 大 |
| 可读性 | 差（得背位定义） | 好 | 最好，但层多 |
| 跨系列移植 | 难 | 中 | 容易 |
| 教学价值 | 高（看清寄存器） | **高（看清外设模型）** | 一般 |

你的教程用标准外设库，是因为它"离寄存器只有一层"，最适合边学边对照手册。工程里还夹着一个 `Public\system.h` 的 **位带宏**（`PAout(n)`/`PBin(n)`）——它不是库，是 Cortex-M 的位带技巧，把"某寄存器的某一位"映射成一个独立地址，所以 `LED1 = !LED1` 只花一条指令。

# 二、LCD 屏幕的知识

## 1. 这块屏是什么类型

**并口 8080 型 TFT（控制器 ILI9341）+ 16 位数据总线**，不是 SPI 屏。它需要这些线：16 根数据线（D0~D15）、片选、**一根"命令/数据"选择线（RS）**、读写选通、复位、背光。

引脚具体分配到哪些 GPIO，看你打开 `APP\tftlcd\tftlcd.c`：
* `TFTLCD_GPIO_Init()`（**1296 行**）—— 把数据/控制脚配成复用推挽给 FSMC
* `TFTLCD_FSMC_Init()`（**1370 行**）—— 配 FSMC 的时序参数（`FSMC_AddressSetupTime` 之类就是读写快慢）
* `LCD_LED = PBout(15)` —— 背光在 `tftlcd.h` 里，PB15

## 2. 核心魔法：把屏当"外部内存"来写

STM32 有个 FSMC 外设，本来是给"外部 SRAM/NOR Flash"用的。这个驱动的做法是**骗 FSMC 说"我接了一块 16 位的内存"**，于是"给屏发命令/数据"就变成了"往某个地址写数据"：

```c
// APP\tftlcd\tftlcd.h
typedef struct { u16 LCD_CMD; u16 LCD_DATA; } TFTLCD_TypeDef;   // 两个成员相差 2 字节
#define TFTLCD_BASE  ((u32)(0x6C000000 | 0x0000007E))          // FSMC Bank1 第 4 区(NE4)
#define TFTLCD       ((TFTLCD_TypeDef *) TFTLCD_BASE)
```

* `0x6C000000` = FSMC Bank1 的第 4 个片选区（NE4）；
* 加上 `0x7E` 是为了让 **A6 这条地址线当 RS 用**：写 `TFTLCD->LCD_CMD` 时 A6=0（命令），写 `TFTLCD->LCD_DATA` 时 A6=1（数据）。
* 你去看 `LCD_WriteCmd()`（**17 行**）和 `LCD_WriteData()`（**97 行**），实现就是各写一次那个成员——**没有别的魔法**。

（头文件注释里提醒的"STM32 内部会右移一位对齐"就是 16 位访问的地址对齐规则，知道有这回事就行，不用自己算。）

## 3. 屏的"命令"就是它的寄存器地址

初始化里你会看到一串 `LCD_WriteCmd(0xXX); LCD_WriteData(0xYY);`，含义是：

| 命令 | 作用 | 本项目里的值 |
|---|---|---|
| `0x3A` | 像素格式 | `0x55` = **RGB565**（一个像素 16 位） |
| `0x36` | 扫描方向 MADCTL | 竖屏 `0x08`、横屏 `0x68`（见 `LCD_Display_Dir`，**376 行**） |
| `0x2A` / `0x2B` | 设列地址 / 行地址（合起来 = 设定窗口） | `LCD_Set_Window`（**666 行**）里发这两条 |
| `0x2C` | 开始写显存 | 上面两条发完后连续写颜色值 |
| `0x11` / `0x29` | 退出睡眠 / 开显示 | ILI9341 初始化序列末尾（带 120ms 延时） |

**这就是为什么颜色要用 RGB565**：一个像素 = 16 位 = 高 5 位 R、中间 6 位 G、低 5 位 B。写颜色时把 24 位的 `#RRGGBB` 直接塞进 16 位参数就会错——我之前踩的坑（深灰变亮蓝）就是这个。

## 4. "画得快"的秘诀：先开窗口，再连续写

`LCD_Set_Window(sx, sy, ex, ey)` 设定一个矩形窗口后，**连续调 `LCD_WriteData_Color()` 会自动按行填充**（写满一行自动换下一行）。所以：

* **按行/按块写** = 一次窗口设置 + N 次连续写 → 快；
* **逐点写**（每个点都 `LCD_Set_Window(x,y,x,y)`）= 每个点 10 次 FSMC 操作 → 慢十几倍。

这就是 `APP\level\ui.c` 里所有图形都"按行 span"实现的原因（`cv_hline`、`cv_disc`、`cv_ring` 全是先算这一行的左右边界，再画一条横线）。

顺便一个教学点：驱动里的 `LCD_Color_Fill()`（**3753 行**）**有性能 bug**——它每写一个像素就重设一次窗口。所以我在 `ui.c` 里完全没用它，只用了 `LCD_Fill()`（**3728 行**，一次窗口 + 循环写）和自己写的 `cv_hline`。

## 5. 驱动里你只要先掌握 6 个函数

| 函数 | 行号 | 干什么 |
|---|---|---|
| `TFTLCD_Init()` | 1429 | 初始化：GPIO + FSMC + 读屏 ID + 按型号发初始化序列 |
| `LCD_Display_Dir(u8)` | 376 | 设横/竖屏（改 MADCTL 并交换 width/height） |
| `LCD_Set_Window(sx,sy,ex,ey)` | 666 | 设定写显存窗口 |
| `LCD_WriteData_Color(u16)` | 191 | 往窗口里写一个像素 |
| `LCD_Fill(x0,y0,x1,y1,color)` | 3728 | 填矩形 |
| `LCD_ShowString(x,y,w,h,size,str)` | 4034 | 显示字符串（字号只支持 **12/16/24**） |

我们自己的代码怎么用它们：`main.c:33-34` 先 `TFTLCD_Init()` 再 `LCD_Display_Dir(1)` 得到 320×240 横屏；之后 `ui.c` 里所有绘制都走"Canvas 抽象 → `cv_*` → `LCD_Set_Window` + `LCD_WriteData_Color`"这条链，完全不碰屏的具体型号。


读回的那 14 个字节怎么用（`level.c:148-164`）：

```c
u8 buf[14];
if (MPU6050_Read_Len(MPU6050_ADDR, MPU6050_ACCEL_XOUTH_REG, 14, buf)) return 1;

a[0] = (short)(((u16)buf[0] << 8) | buf[1]);   // 加速度 X  ← buf[0..5] = ax,ay,az
a[1] = ...                                     // 加速度 Y
a[2] = ...                                     // 加速度 Z
*t   = (short)(((u16)buf[6] << 8) | buf[7]);   // 温度      ← 0x41/0x42
g[0] = (short)(((u16)buf[8] << 8) | buf[9]);   // 角速度 X  ← buf[8..13] = gx,gy,gz
```

**为什么不用现成的 `Get_Accelerometer/Get_Gyroscope`**：那两个函数各自会发起一次独立的 I2C 事务（起始→地址→寄存器→起始→读→停止）。我们的 `Read_Len` 一次把加速度+温度+角速度全读回来，**1 次事务顶 3 次**，100Hz 采样下省掉 2/3 的通信时间。这就是"看懂例程、然后自己做取舍"的典型例子——不是例程错，是需求不同。

## 第六段：主循环（第 74–129 行）—— 全篇最该吃透的部分

### 6.1 先取一次时间，把四个时间戳对齐（74–78）

```c
now   = LEVEL_Us();          // 读一次 TIM2 的微秒计数
t_ui  = now;                 // 四个"上次执行时刻"全部初始化成当前时刻

t_sec = now;
t_ser = now;
```

**为什么必须先取一次**：如果 `t_ui` 还是 0，那么第一次算 `(now - t_ui)` 会得到一个巨大的数（几百万微秒），四个任务会立刻同时触发一次，等于"开机瞬间全挤在一起"。初始化成同一个时刻，就能让每个任务从各自的周期开始。

### 6.2 采样：无条件、每圈都执行（80–83）

```c

{
    LEVEL_Update();          // 读一次传感器 + 走一步滤波，约 1ms
```

`LEVEL_Update()` **不做任何判断、每圈必调**——这是有意的：采样率要尽量稳定（滤波的 `dt` 由函数内部实测），不能因为"这圈忙"就跳过一次。

### 6.3 四个软定时任务（85–122）

```c
    now = LEVEL_Us();        // 每圈只读一次时间，四个判断共用（保证同一时刻判断）

    if ((u32)(now - t_ui)  >= 50000u)   { t_ui  = now; UI_Update(); fps++; }   // 20Hz 刷屏
    if ((u32)(now - t_led) >= 500000u)  { t_led = now; LED1 = !LED1; }          // 1Hz 心跳灯
    if ((u32)(now - t_sec) >= 1000000u) { t_sec = now; fps_show = fps; fps = 0; UI_SetFps(fps_show); }
    if ((u32)(now - t_ser) >= 500000u)  { ...拼一行字符串... printf("%s\r\n", sbuf); }  // 2Hz 遥测
```

这里有两个必须懂的点：

1. **`(u32)(now - t_ui) >= 50000u` 这个写法**：`now` 和 `t_ui` 都是 32 位无符号数，**无符号减法在溢出时自动回绕**，所以即使计数器走过 0（TIM2 大约 71 分钟回绕一次），差值依然正确。反过来如果你写成 `if (now >= t_ui + 50000)`，回绕那一刻就会**永远不再触发**——这是嵌入式里非常经典的坑。
2. **各任务周期的分层理由**：
   * 传感器 100Hz：滤波效果依赖采样密度，快；
   * 屏幕 20Hz：人眼够用，而刷屏最贵（每帧要写几 KB 到 LCD）；
   * 心跳灯 500ms 翻转 = **1 秒一个完整周期**；
   * 串口 2Hz：115200 下一行约 100 字符要 **8.7ms 阻塞**，打太快会把整个循环拖垮。

### 6.4 遥测为什么用 `LEVEL_FmtF` 而不是 `printf("%f")`（105–121）

```c

...
sprintf(sbuf, "[LV] P%s R%s T%s | A%s %s %s | G%s %s %s | ZN%d ST%d AX%d F%d", ...);

```

* **不用 `%f` 的原因**：`%f` 会牵进浮点格式化代码，Flash 多占几 KB，而且小数位/小数点对齐不可控；自己写定宽输出，串口里每一列的宽度永远一致，方便肉眼比对和上位机解析。
* `sprintf` 把整行拼好后一次 `printf`，也是"少调用、少阻塞"的思路。

## 阶梯 0：一个像素是用一个 16 位数字表示的

屏是 320×240 = **76800 个点**，每个点一个 16 位颜色值，格式叫 **RGB565**：

```
 RRRRR GGGGGG BBBBB      → 高5位红、中6位绿、低5位蓝
 红32级  绿64级  蓝32级
```

`APP\tftlcd\tftlcd.h` 里那一堆颜色宏就是这些数字：

```c
#define WHITE  0xFFFF   // 全亮
#define BLACK  0x0000   // 全灭
#define RED    0xF800   // R=31,G=0,B=0
#define GREEN  0x07E0   // R=0,G=63,B=0
#define BLUE   0x001F   // R=0,G=0,B=31
#define YELLOW 0xFFE0   // 红+绿
#define CYAN   0x7FFF
#define GRAY   0x8430
```

**自己怎么算**（记住这个练习，以后调色全靠它）：

```
c = ((r >> 3) << 11) | ((g >> 2) << 5) | (b >> 3)
```

拿一个实际颜色试：`#FF4D5E` → r=255, g=77, b=94
r>>3 = 31，g>>2 = 19，b>>3 = 11 → `31<<11 | 19<<5 | 11` = **0xFA6B**。
（这就是我在 `ui.c` 里定义的"警示红"。）你随便挑个颜色自己算一遍，算完我们可以核。

> ⚠️ 这也是我之前踩的坑：把 `#0B3A46` 这种 **24 位**数字直接塞进 16 位参数，高位被截断，深灰会变成亮蓝色。**24 位的必须转换**。

## 阶梯 2：为什么逐点慢 —— "一次设窗口，连续写"

逐点画 300 个点 = 300 次 `LCD_Set_Window`。而 `LCD_Set_Window` 每次要发 0x2A/0x2B/0x2C 一堆命令，**10 次总线操作**。所以：

```c
LCD_Set_Window(10, 30, 309, 30);        // ① 只设一次窗口：高度 1 像素
for (i = 0; i < 300; i++)
    LCD_WriteData_Color(0x07E0);        // ② 连续写 300 次，自动往右推进
```

快了大约 **10 倍**。库已经帮你封装好了：

```c
LCD_Fill(x0, y0, x1, y1, color);        // tftlcd.c:3728，内部就是"一次窗口 + 循环写"
LCD_Clear(color);                       // tftlcd.c:3710，等于填满整屏
```

**第二课**：想快，就"少设窗口、多写像素"。`ui.c` 里所有图形都按这个原则写成"按行 span"，就是这一步的延伸。

顺便教你量性能（用我们自己的微秒计时器）：

```c
u32 t0 = LEVEL_Us();
LCD_Clear(BLACK);
printf("clear = %u us\r\n", (unsigned)(LEVEL_Us() - t0));
```

整屏 76800 像素，看看你的板子花多少微秒——这个数字决定了你的界面最高能跑多少帧。

## 阶梯 3：画一条线（斜线靠 Bresenham）

库里有现成的：`LCD_DrawLine_Color(x1,y1,x2,y2,color)`（**3825 行**）。核心思想（每个 x 前进一步，判断 y 要不要也走一步）：

```c
xerr += delta_x;  yerr += delta_y;
if (xerr > distance) { xerr -= distance; x++; }   // 横向走够了，x 才进一格
if (yerr > distance) { yerr -= distance; y++; }   // 纵向走够了，y 才进一格
```

这样画出来的线段**没有断点、也不会重复涂**，是显示器的标准画线算法。

练手：在屏幕中间画个"米"字（4 条线 + 十字）：

## 阶梯 5：圆和圆环（就是勾股定理）

两种实现，你都看一遍：

```c
FRONT_COLOR = 0xF800;
LCD_Draw_Circle(80, 180, 30);            // 库函数（3903 行）：中点画圆，一次画 8 个对称点
```

它内部是"x 从 0 扫到 r，算 y = √(r²−x²)，然后一次画 8 个对称点"。

而**填圆/圆环**（`ui.c` 里的靶心用的）更快，思路是**按行**：对每一行 y 算出半宽 dx = √(r²−y²)，然后画一条横线：

```c
/* 实心圆：每行一条横线 */
for (y = -r; y <= r; y++) {
    dx = (int)sqrt((float)(r*r - y*y));
    LCD_Fill(cx - dx, cy + y, cx + dx, cy + y, color);   // 这一行从 cx-dx 填到 cx+dx
}
```

一个圆 = 2r 次 `LCD_Fill`，比"逐点判距离"快得多。**这就是 `ui.c` 里 `cv_disc`/`cv_ring` 的全部秘密**。

练手：画靶心雏形——三个同心圆，半径 15/30/45，红/黄/绿：

```c
FRONT_COLOR = 0xF800; LCD_Draw_Circle(160, 120, 15);
FRONT_COLOR = 0xFFE0; LCD_Draw_Circle(160, 120, 30);
FRONT_COLOR = 0x07E0; LCD_Draw_Circle(160, 120, 45);
```

这已经长得像水平仪靶心了 —— `ui.c` 就是在这个基础上加了渐变、刻度、和"每帧只重画气泡"的优化而已。

# 一、先纠正一个印象：MPU6050 不是"一个传感器"

它是**一块硅片上装了两个完全不同的传感器**，还外加一个温度计：

| 里面有什么 | 数量 | 测什么 | 单位 | 强项 | 弱项 |
|---|---|---|---|---|---|
| **加速度计** (Accelerometer) | 3 轴 | 重力/比力 | g | **长期准**（永远指向重力） | 短期吵，一碰就跳 |
| **陀螺仪** (Gyroscope) | 3 轴 | 旋转**角速度** | °/s (dps) | **短期准**，不怕振动 | 积分会累积漂移，还有零偏 |
| 温度计 | 1 | 芯片温度 | ℃ | 用来做温补 | 精度一般 |

**最关键的一点（直接回答你的问题）**：

> **两个传感器共用同一套轴 Sx / Sy / Sz。**

它们做在同一块硅片上，加速度计的 X 轴和陀螺仪的 X 轴就是**同一根物理轴**。所以：

* 板子上的装配朝向（传感器转了 90°）**对两个传感器同时成立**；
* 你改了"哪根加速度轴对应屏幕的哪个方向"，就必须同时改"哪根陀螺轴对应屏幕的哪个方向"——**它们是一套坐标系，不是两套**。

而且还有个容易踩的细节：**它们是"交叉配对"的**，见下面第三节。

---

# 二、一个角度有"两种测法"——滤波就是把这俩加权

拿 `pitch` 举例，它代表"板子绕某根轴倾斜了多少度"。这个角度可以有两种独立测法：

| 测法 | 怎么做 | 特点 |
|---|---|---|
| **重力测法**（加速度计） | 倾斜时重力会"漏"到某个轴上：`ap = atan2(某轴, az)` | 绝对、不漂；但噪声大 |
| **积分测法**（陀螺仪） | 角速度乘时间就是角度增量：`pitch += ω · dt` | 平滑、跟手；但零偏会让它慢慢漂 |

互补滤波就是把两者加权：

```c
pitch = 0.98f * (pitch + ω * dt) + 0.02f * ap;
/*      └── 97% 信陀螺的积分 ──┘   └ 2% 用重力纠正 ┘ */
```

* `0.98 / 0.02` 的比例决定"时间常数"：`τ ≈ dt/(1-K) = 0.01/0.02 = 0.5 秒`——意思是"重力大约每 0.5 秒把漂移拉回来一次"；
* K 越大越平滑但越"拖"，K 越小越跟手但越抖。

**这就是为什么同一个公式里既有 `a*` 又有 `g*`：它们在测同一个角度，只是测法不同。**

---

# 三、为什么必须"交叉配对"（你这次改轴的核心）

角度是"**绕某根轴**转了多少"，所以两种测法必须指向**同一根旋转轴**：

| 转动 | 陀螺给的是 | 重力漏到哪根加速度轴 | 角度公式 | 配对的陀螺项 |
|---|---|---|---|---|
| 绕 **X 轴**转（把 +Y 那条边抬起来） | `gx` | `ay`（`az` 变小） | `θ = atan2(ay, az)` | **`+ gx · dt`** |
| 绕 **Y 轴**转（把 +X 那条边抬起来） | `gy` | `ax` | `θ = atan2(ax, az)` | **`- gy · dt`** |

看出"交叉"了吗：**重力用的是"垂直于转轴的那根轴"（ay），陀螺用的是"转轴本身"（gx）**。这不是随便写的，是几何关系决定的：

* 绕 X 轴转 → 重力在 Y 方向的分量变化 → 所以看 `ay`；
* 而"转得多快"这件事，只有 `gx` 知道。

**原来的代码**（`pitch = atan2(ay,az)` 配 `+gx`、`roll = atan2(ax,az)` 配 `-gy`）本来就是一对自洽的组合。
**你改了轴以后**：`pitch` 现在描述的是"绕 **Y** 轴的转动"（因为用的是 `ax`），所以它的角速度必须是 `gy` —— 于是 `+ gx·dt` 变成 `- gy·dt`。**如果你不改陀螺项，会发生什么**：

> 重力说"板子绕 Y 轴转了"，陀螺却在报告"绕 X 轴转了多少"——滤波把两个不同物理量混在一起。
> 静止时看不出来（角速度≈0），**一晃板子气泡就会朝错误方向抢跑，再被重力慢慢拉回来**，看着像"发飘/不受控"。

## 数据区布局（`0x3B` 起 14 字节，高字节在前、16 位补码）

| 字节 | 内容 | 拼接写法 |
|---|---|---|
| 0~1 | 加速度 X | `(short)((buf[0]<<8) \| buf[1])` |
| 2~3 | 加速度 Y | 同理 |
| 4~5 | 加速度 Z | 同理 |
| 6~7 | **温度** | `T(℃) = raw/340 + 36.53` |
| 8~9 | 角速度 X | 同理 |
| 10~11 | 角速度 Y | 同理 |
| 12~13 | 角速度 Z | 同理 |

> 为什么要拼高字节：芯片是"大端"输出，先发高位。`buf[0]` 是 s8 类型时不能直接 `<<8`（符号位会捣乱），所以要先转 `u16` 再移位——这就是 `(short)(((u16)buf[0]<<8)|buf[1])` 的由来。

## 量程 → 换算系数（必须与寄存器设置一致！）

| 加速度量程 | 灵敏度 | | 陀螺量程 | 灵敏度 |
|---|---|---|---|---|
| ±2 g | **16384** LSB/g | | ±250 dps | 131 LSB/(°/s) |
| ±4 g | 8192 | | ±500 dps | **65.5** |
| ±8 g | 4096 | | ±1000 dps | 32.8 |
| ±16 g | 2048 | | ±2000 dps | 16.4 |

我们代码用的是 **±2g（16384）** 和 **±500dps（65.5）**：

```c
float fax = a[0] / 16384.0f;              /* 原始整数 -> g */
float gx  = (g[0] - bx) / 65.5f;          /* 先扣零偏, 再 -> °/s */
```

**教训**：改量程宏忘了改系数，所有角度会成比例错（这正是我让你在 STEP 8 之前做过的那个"故意错"实验）。

## 三个"芯片脾气"你必须知道

1. **上电默认睡眠**：不写 `0x6B` 唤醒，读回来的数据全是 0。
2. **陀螺有零偏**：datasheet 允许静止时输出 ±20 dps 的偏差（换算成原始值就是上千）。不扣掉，积分一秒钟就漂好几度——所以我们开机静止采 100 次求平均（`bx/by/bz`）。
3. **加速度计怕振动、陀螺怕时间**：这就是互补滤波存在的理由。

# 五、回到你那 4 行，现在逐行读一遍

```c
float ap  = atan2f(fax,  faz) * 57.29578f;   /* 重力测法: 这次用 ax —— 因为这板子上传感器转了 90° */
float ar  = atan2f(-fay, faz) * 57.29578f;   /* 重力测法: 负号是为了让"抬右端 = roll 为正" */
float gx  = (g[0] - bx) / 65.5f;             /* 陀螺测法: 扣零偏 -> 换成 °/s */
float gy  = (g[1] - by) / 65.5f;
...
pitch = 0.98f * (pitch - gy * dt) + 0.02f * ap;  /* 绕 Y 轴的转动: 陀螺用 gy, 重力用 ax  */
roll  = 0.98f * (roll  - gx * dt) + 0.02f * ar;  /* 绕 X 轴的转动: 陀螺用 gx, 重力用 ay  */
```

对照第三节那张表看：
* `pitch` 现在由 `ax` 算 → 它描述"绕 **Y** 轴" → 陀螺项必须是 `gy` ✅ 你改对了（`+gx` → `-gy`）；
* `roll` 现在由 `-ay` 算 → 它描述"绕 **X** 轴"（带负号） → 陀螺项 `-gx` ✅ 你改对了（`-gy` → `-gx`）。

**一句话总结**：`a*` 和 `g*` 是同一个角度的两种测法；"绕哪根轴"这件事把它们锁在一起——**换轴必须成对换，符号由"抬起来读数为正"这条规则定**。

static void step6_filter(void)

    printf("[6] ±£³Ö¾²Ö¹, ±ê¶¨ÍÓÂÝÁãÆ«ÖÐ ...\r\n");

        }
        delay_ms(10);                            /* 10ms Ò»´Î, ºÍÐ¾Æ¬ 100Hz ²ÉÑù¶ÔÆë */

    }
    printf("[6] ÁãÆ« = %d %d %d (Ô­Ê¼Öµ)\r\n", (int)bx, (int)by, (int)bz);
    printf("[6] ¶Ô±ÈÏÂÃæÁ½ÁÐ: ¼ÓËÙ¶È½Ç»á¶¶, ÂË²¨ºó»áÎÈ\r\n");

            if (dt < 0.001f) { dt = 0.001f; }

            {

static void step7_level(void)

    float pitch = 0, roll = 0;
    float zp = 0, zr = 0;                        /* ¹éÁã»ù×¼ */

            last = now;
