# 题目2 要求与坑点审查

> 审查对象：`2026创新基地班软件考核-第二题.docx`、`软件第二题_测评表_空表.docx`、`第二题例程`（CORE/FWLIB/SYSTEM/HARDWARE/USER）。
> 结论先说：这道题**不是"会不会写定时器"**，而是"**在一个没有图形库、没有帧缓存、字库还很残缺的 240x320 屏上，把 PWM、捕获、UI、时间基准四条线同时跑稳**"。基本功能 43 分必须拿满；拓展按性价比做。

---

## 0. 先看结论（时间不够时只看这一节）

1. **基本盘 43 分**：PWM 15 分 + 菜单/键盘 12 分 + 捕获 10 分 + 秒表 6 分。先把这 43 分做稳，再碰拓展。
2. **最容易翻车的三件事**：
   - 屏幕字库：**中文只有 4 个字**（"伍陆电子"），`LCD_ShowString` 遇到中文直接停；界面必须全英文。
   - 触摸：例程是**电阻屏 + 软件 SPI**，校准参数存在 24C02；换屏幕方向、换板子、EEPROM 掉参数都会导致"点不准"。上电自动进校准会浪费演示时间。
   - 时间基准：`delay.c` 把 **SysTick 当查询式延时**用了，`SysTick_Handler` 是空的；你再用 SysTick 做 1ms 节拍会和 `delay_us` 打架。用 TIM6 单独做节拍。
3. **PWM 的 1% 占空比**：200kHz 时 168MHz 定时器一个周期只有 840 个数，1% 只有 8.4 个数；低频段又必须保证 ARR 足够大。**PSC 和 ARR 必须一起算**，只改一个高频段必挂。
4. **输入捕获**：1Hz 周期是 8400 万个数，**16 位定时器必溢出**；用 32 位的 TIM5/TIM2，或者做量程切换。
5. **触摸与 PWM 不阻塞**：PWM 是硬件发的，本来就不会停；真正会卡的是 UI 里的 `delay_ms`、全屏重画、`printf`。主循环里不许有等待。
6. **验收不能按 RESET、不能重新烧录**：所有功能必须能从界面点进去；上电不能卡在触摸校准；最终 hex 要先烧好、全流程走一遍。

## 1. 题目与评分拆解

### 1.1 基本功能（43 分）

| 项 | 要求 | 分值 | 验收方式 |
|---|---|---:|---|
| PWM 频率/占空比 | 1Hz～200kHz，占空比 0%～100%，1% 一档，全频段 | 8 | 示波器比对，频率/占空比误差 ≤1% 不扣 |
| 0% / 100% 边界 | 0% 恒低、100% 恒高，无窄脉冲毛刺 | 4 | 示波器看两端 |
| 改参数立即生效 | 过渡不超过一个周期，不丢输出 | 3 | 改完立刻看波形 |
| 菜单界面 | 功能菜单 + 参数显示/修改 | 5 | 菜单项齐全、可改可退、不闪屏无残影 |
| 数字键盘 | 3×4（0～9、删除、确认） | 7 | 布局正确、点击有响应、有效值与修改值可区分 |
| 输入捕获测频 | 1Hz～200kHz，误差 ≤1%，2 秒内跟随 | 6 | 信号源比对 |
| 输入捕获测占空比 | 高电平/周期，误差 ≤2% | 4 | 信号源比对 |
| 秒表 | 定时器正计时，暂停/重置，毫秒；圈计时+分段计时 | 6 | 操作检查 |

**误差扣分细则（测评表原文）**：
- 误差 = |实测 − 设定| ÷ 设定 × 100%；
- 频率取全频段最差频点；占空比在 **10% / 50% / 90%** 三点各测一次取最差；
- PWM 输出：≤1% 不扣，≤2% 扣 1 分，≤5% 扣 2 分，≤10% 扣 3 分，>10% 记 0；
- 捕获测频：≤1% 不扣，≤2% 扣 1，≤5% 扣 2，≤10% 扣 3，>10% 记 0；
- 捕获占空比：≤2% 不扣，≤5% 扣 1，≤10% 扣 2，>10% 记 0。

> 注意：占空比误差公式按原文也是"相对误差"写法，但占空比在 1% 这种小值时相对误差会被放大。**验收实际测 10/50/90 三个点**，所以先把这三个点做准；同时尽量把全范围的整数取整误差压小。

### 1.3 文字里容易看错的点

1. **"可圈计时和分段计时（）"**：括号里是空的，没给定义。按通用定义做：
   - 圈计时 lap = 距上一次按"圈"的时间（本圈用时）；
   - 分段计时 split = 按"圈"那一刻的总时间（累计）。
   两个都显示，答辩时能解释清楚。
2. **"两路互相独立，频率和第一路一样可调"**：第二路的**频率跟随第一路**，不是两路各自设不同频率；"独立"指占空比/相位可独立调。
3. **"0% 与 100% 边界，无低电平毛刺"**：100% 不是 `CCR=ARR`（那是 99.9%），而是 `CCR=ARR+1`；`ARR` 不能取 65535，否则 +1 溢出回 0，直接变 0%。
4. **"改参数后输出立即生效，过渡不超过一个周期"**：允许有一个周期的过渡，但不允许停振、不允许长时间无输出。
5. **"整个频率范围内都要满足这一档精度"**：1Hz 和 200kHz 都要能设到；1% 是**步进**，误差按上面的细则算。
6. **"触摸与 PWM 输出互不阻塞"**：硬件 PWM 不会因为 UI 卡而停；但如果你在 UI 里 `delay_ms(1000)`，触摸、捕获显示、扫频都会卡。**主循环禁止阻塞**。
7. **"不得额外导入图形库"**：只能用 `tftlcd.c/h + font.H`；LVGL、emWin、u8g2 一律不许。按钮、键盘、滑条全部自己用画点/线/矩形/填充拼。
8. **"不允许按 RESET、不允许重新烧入代码"**：最终演示必须一次上电走完；上电自动校准、HardFault、看门狗复位都算事故。
9. **"验收时可能现场改参数（频率上下限、占空比步进），限 3 分钟"**：所有这类参数必须集中在一个头文件里，改一行、重编译、能演示。不要散落在各个 `.c`。
10. **"拓展部分不要求全做，做几条算几条"**：先保基本盘，拓展按性价比排序，不要为了凑数量把已经跑通的基本功能改崩。

## 3. 工程与硬件事实（已核对例程）

### 3.1 时钟与定时器

- HSE = **8MHz**（`stm32f4xx.h` 的 `HSE_VALUE`）。
- PLL：`PLL_M=8, PLL_N=336, PLL_P=2` → **SYSCLK = 168MHz**。
- APB1 = 42MHz，APB1 定时器时钟 = **84MHz**（TIM2/3/4/5/6/7/12/13/14）。
- APB2 = 84MHz，APB2 定时器时钟 = **168MHz**（TIM1/8/9/10/11）。
- 这意味着：
  - 200kHz 主 PWM 用 TIM1/TIM8：**840 ticks/周期**；
  - 若用 TIM2-5：**420 ticks/周期**，1% 只剩 4.2 ticks，高频占空比精度明显更差；
  - 输入捕获用 TIM5（32 位，84MHz）：1Hz 周期 8400 万 counts，刚好放得下。
- `delay.c` 用 SysTick 的查询模式，`SysTick_Handler` 在 `stm32f4xx_it.c` 里是空的。**不要拿 SysTick 做 UI 节拍**。

### 3.2 屏幕

- 驱动：`TFTLCD_ILI9341`，FSMC Bank1 NORSRAM4，16 位并口。
- 默认方向：`TFTLCD_DIR = 0`，**竖屏 240（宽）×320（高）**。
- `LCD_Display_Dir(0)` 对 ILI9341 写 `MADCTL=0x08`，`width=240, height=320`。
- 背光：`PB15`（`LCD_LED`），高电平点亮。
- 没有帧缓存：所有画图直接写 FSMC；`LCD_Clear` 是 240×320=76800 次写，**不要在循环里整屏清**。
- `LCD_Fill` 是矩形填充的快路径；`LCD_ShowChar` 是**逐像素**调 `LCD_DrawFRONT_COLOR`，每个像素都 `LCD_Set_Window`，所以文字比填充慢很多。
- `LCD_Color_Fill` 的实现是"每个像素设一次窗口"，大区域不要用它。
- 支持的颜色宏在 `tftlcd.h`：`WHITE/BLACK/RED/GREEN/BLUE/GRAY/LGRAY/YELLOW...`，RGB565，无 alpha。

### 3.3 字库（本工程最大的坑）

`font.H` 里实际有：
- `ascii_1206[95][12]`：12 号 ASCII，6×12；
- `ascii_1608[95][16]`：16 号 ASCII，8×16；
- `ascii_2412[95][36]`：24 号 ASCII，12×24；
- `ascii_3216[95][128]`：32 号 ASCII 数据存在，但 **`LCD_ShowChar` 只处理 12/16/24，32 号直接 `return`**；
- `hanzi_1212[95][24]`：名字像汉字，实际是 **95 个 ASCII 的 12×12 点阵**；
- `CnChar32x29[]`：**只有 4 个汉字**——"伍、陆、电、子"，32×29。

由此得到几条硬规则：
1. **界面文字全部用英文/数字**。`LCD_ShowString` 的判断是 `*p <= '~' && *p >= ' '`，遇到中文字节直接停止，后面的字不会显示。
2. **不要用 `LCD_ShowChinese12x12` 显示中文**，它就是 ASCII 12×12；名字有误导。
3. **`LCD_ShowFontHZ` 只能显示"伍陆电子"四个字**，而且只扫描 `CnChar32x29[0..19]`；找不到时只画背景。它按 GBK 双字节比较，源文件/字符串编码不对也匹配不上。
4. 24 号字每字符 12px 宽，240px 宽一行最多 20 个字符；16 号 8px，最多 30 个；12 号 6px，最多 40 个。布局先算宽度。

### 3.4 触摸与 EEPROM

- 电阻屏控制器（ADS7846/XPT2046 兼容），**软件 SPI**：
  - `TCLK=PB0`，`PEN=PB1`，`DOUT=PB2`，`TCS=PC13`，`TDIN=PF11`。
- 触摸库流程：`TP_Init()` → `AT24CXX_Init()` → `TP_Get_Adjdata()`；如果没有校准标记，进入 `TP_Adjust()` 四点校准，**阻塞等待**，10 秒超时。
- 校准参数存在 24C02 的 `SAVE_ADDR_BASE=200`，标记字节在 `200+13=213`，值为 `0x0A` 表示已校准。
- `TP_Scan(0)` 返回屏幕坐标；`tp_dev.sta`：
  - bit7 = 当前按下；
  - bit6 = 有一次新按下（`TP_CATH_PRES`）；
  - 松开后 `tp_dev.x[0]/y[0]` 会被设成 `0xFFFF`。
- `TP_Scan` 内部一次完整扫描最多做 **160 次 AD**（40 次 × X/Y 两轴 × `TP_Read_XY2` 的两次读取），每次还要冒泡排序、丢最大最小取平均，**单次扫描是毫秒级**，不要每轮主循环都扫。
- 触摸校准是在**当前屏幕方向**下做的；`TP_Adjust` 用 `tftlcd_data.width/height` 算系数。**改成横屏后必须重新校准**，否则坐标全错。
- 换一块屏/换一块板/EEPROM 掉电，旧校准都可能失效；演示前一定先点一遍。

### 3.5 已占用引脚与可用引脚

例程已占用：

| 功能 | 引脚 |
|---|---|
| LCD FSMC | PD0/PD1/PD4/PD5/PD8/PD9/PD10/PD14/PD15，PE7～PE15，PF12，PG12 |
| LCD 背光 | PB15 |
| 触摸 | PB0/PB1/PB2/PC13/PF11 |
| USART1 | PA9/PA10 |
| EEPROM IIC | PB8/PB9 |
| LED | PF9/PF10 |

本框架默认选的（都在上面之外，但**必须对照你板子的排针确认**）：

| 用途 | 定时器/通道 | 引脚 | 备注 |
|---|---|---|---|
| 主 PWM | TIM1_CH1 | PA8 | 168MHz，高级定时器，必须开 MOE |
| 第二路/相位 | TIM8_CH1 | PC6 | 168MHz，高级定时器，必须开 MOE |
| 输入捕获 | TIM5_CH1 | PA0 | 32 位；部分板 PA0 是 WK_UP，注意 |
| SPWM | TIM3_CH1 | PA6 | 84MHz；PA6 也是 SPI1_MISO，本工程没开 SPI1 |
| 1ms 节拍 | TIM6 | 无 | 基本定时器，只开中断 |

> 如果 PA0 被 WK_UP 占用，可改 TIM2_CH1/PA5（TIM2 也是 32 位）。但 **PWM 输入模式必须用 CH1/TI1**，不能随便换到 CH2。

### 3.6 资源

- Flash 1MB，SRAM 128KB + CCM 64KB。
- 启动文件：`Stack_Size = 0x400`（**1KB 栈**），`Heap_Size = 0x200`（512B 堆）。
- 结论：
  - **不要 malloc**；所有大数组用 `static`/全局；
  - 不要在函数里放几百字节的局部数组（栈只有 1KB）；
  - `sprintf` 缓冲区要小（64～128B），且避免深调用；
  - 400 点正弦表、400 格贪吃蛇数组都放全局。

### 3.7 工程/编译

- Keil MDK，ARMCC **V5.06 update 5**，C99 打开。
- 宏定义：`STM32F40_41xxx, USE_STDPERIPH_DRIVER`。
- FWLIB 全部编译（包括 tim/gpio/rcc/fsmc/usart/misc）。
- 原例程 `main.c` 只是红/蓝屏交替 + `delay_ms(1000)`，**不要照抄它的循环结构**。
- 源文件编码是混合的：大部分 `.c/.h` 是 GBK，`font.H` 里既有 UTF-8 注释又有 GBK 的 `Index` 字节。新文件统一用 GBK 保存，界面字符串只用 ASCII。

## 4. 坑点清单

> 严重度：★★★ = 直接丢分/演示翻车；★★ = 明显影响效果；★ = 细节。
> 每条都给了"现象/原因/对策"，可以当排错手册用。

### 4.1 屏幕、字库、UI

| ID | 坑 | 现象/原因 | 对策 |
|---|---|---|---|
| P01 ★★★ | 想显示中文 | `LCD_ShowString` 遇到非 ASCII 直接停；`CnChar32x29` 只有"伍陆电子"4 个字 | 界面全英文；中文只做 logo |
| P02 ★★★ | 用 `LCD_ShowChinese12x12` 显示中文 | `hanzi_1212` 实际是 95 个 ASCII 的 12×12 | 不要用；要中文只能用 `LCD_ShowFontHZ` 那 4 个字 |
| P03 ★★★ | `LCD_ShowFontHZ` 越界读 | 数组 `CnChar32x29[]` 只有 **4 项**，函数却 `for(wordNum=0; wordNum<20; wordNum++)` 扫 20 项，越界读 16 项；找不到字时可能读到垃圾并画出乱码 | 不要用它显示未知字符；只显示"伍陆电子"；更不要拿它做通用中文字库 |
| P04 ★★ | 汉字画出界 | `LCD_ShowFontHZ` 无边界检查，32×29 从 x/y 开始画 | x<=208、y<=291；否则别用 |
| P05 ★★★ | 用 32 号字 | `LCD_ShowChar` 只支持 12/16/24，32 号直接 return | 最大用 24 号 |
| P06 ★★ | 文字宽度算错 | 12/16/24 号每字符宽 6/8/12px | 先算一行多少字，再定 x |
| P07 ★★★ | `LCD_ShowString` 的 width/height 传成终点坐标 | 它是"区域宽/高"，不是 x2/y2；传错会提前换行/截断 | 传可用宽度和高度 |
| P08 ★★ | 数字变短后留残影 | `LCD_ShowNum` 高位画空格，长度变了就擦不干净 | 固定 len；或 `LCD_ShowxNum(...,0x80)` 补 0 |
| P09 ★★ | 文字背景色不对 | `LCD_ShowChar` 用全局 `BACK_COLOR` 填背景 | 画字前把 `BACK_COLOR` 设成该区域底色 |
| P10 ★★ | 颜色串了 | `FRONT_COLOR`/`BACK_COLOR` 是全局的，任何画图函数都可能改 | 每个图元画之前显式设色；或封装 `UI_TextColor` |
| P11 ★★★ | 循环里 `LCD_Clear` | 76800 次 FSMC 写，明显闪屏 | 只在换页清一次；同页用局部填充 |
| P12 ★★ | 用 `LCD_Color_Fill` 刷大区域 | 实现是每像素设一次窗口，极慢 | 用 `LCD_Fill` |
| P13 ★★ | 每帧重画全部文字 | `LCD_ShowChar` 逐像素设窗口，很慢 | 只重画变化的数字/区域，脏标记 |
| P14 ★★ | 坐标越界 | `LCD_Fill`/`LCD_DrawRectangle` 不检查 x2/y2 是否超屏 | 封装里 clamp 到 0..239/0..319 |
| P15 ★★★ | 竖屏/横屏混了 | `TFTLCD_DIR=0` 是 240×320 竖屏；改横屏要改宏并重校准 | 先定方向，再写布局；改方向必重校准 |

## 5. 分项实现要点（只给约束，不给你算法）

### 5.1 PWM
- 主 PWM 用 TIM1_CH1/PA8（168MHz）；第二路用 TIM8_CH1/PC6（168MHz）。
- 计算顺序：先算总 ticks，再拆 PSC/ARR，最后按 ARR 算 CCR。
- ARR 要尽量大：至少 100（1% 档），最好几千；200kHz 时只有 840，要接受量化。
- 0%：CCR=0；100%：CCR=ARR+1；ARR≤65534。
- 改参数：先写 PSC/ARR，再写 CCR，最后统一更新；允许一个周期过渡。
- 验证点：1Hz、100Hz、1kHz、10kHz、100kHz、200kHz × 10%/50%/90%。

### 5.2 输入捕获
- TIM5_CH1/PA0，32 位，PSC=0，PWM 输入模式（CH1 上升/CH2 下降/从模式复位）。
- 中断只存 CCR1/CCR2/序号/时间；主循环算频率/占空比。
- 1Hz 时等 1 个周期就是 1s；2 秒内出数是硬指标。
- 200kHz 时 1 tick≈0.238%；占空比小值要平均/插值。
- 超时 3s 判无效；界面显示"---"。
- 信号源≤3.3V、共地、串阻/钳位。

### 5.3 秒表
- 用 TIM6 1ms tick；运行中 `elapsed = base + (now - start)`。
- 暂停时把差值累加到 base；重置全清。
- lap=本圈，split=累计；显示 00:00.000。
- 刷新 20～30Hz，固定宽度。

### 5.4 菜单/键盘
- 240×320 竖屏；菜单 8 行×32px；选中行高亮。
- 键盘 3×4，键≥70×40；数字/删除/确认；按下反馈。
- 编辑值黄色、实际值青色；确认前不生效。
- 所有页面可达；返回路径清晰。

### 5.5 相位
- 同一定时器两个通道的上升沿天然对齐，不能直接做任意相位。
- 选一种：主从触发+计数器偏移 / 高级定时器组合 PWM / 一次性 ARR 滑动。
- 调相位时不能停输出；频率跟随 CH1；5° 一档。
- TIM8 要开 MOE。

### 5.6 滑动条
- 三态：DOWN 记录 grab_dx；MOVE 实时映射；UP 保留最后值。
- 只重画轨道/滑块；clamp 0..100；按当前模式 1%/5% 步进。

### 5.7 扫频
- 12 个点，10Hz～200kHz；每点等待 400ms；状态机非阻塞。
- 用 seq 判断新数据；误差 0.01% 单位；表格 12 行。
- 回环线 PA8→PA0；PASS/FAIL；可 ABORT。

### 5.8 SPWM
- TIM3_CH1/PA6，84MHz，载波 20kHz（ARR=4199），400 点→50Hz。
- 正弦表全局；中断查表写 CCR；RC 滤波截止约 500Hz。
- 输出幅度留 10% 余量；不要削顶。

### 5.9 500kHz
- 168MHz/336=500k；ARR=335；占空比 5% 档。
- 捕获 84MHz→168 ticks；filter=0；平均。
- 做模式切换，保留 200k/1% 基本功能。

### 5.10 贪吃蛇
- 20×20 格，12px；160ms 一步；只重画变化格。
- 手动/自动/暂停/重开/计分；自动模式保证不困死。
- 离开页面暂停。

题目明确可能让你改"频率上下限、占空比步进"。建议：

4. 提前演练一次：改宏 → 编译 → 烧录 → 演示，控制在 3 分钟内。
5. 如果验收允许在 UI 里改，做一个"设置"页更稳；但不要把基本功能改坏。

## 9. 答辩可能被问的问题

1. 为什么主 PWM 用 TIM1 而不是 TIM2？→ 时钟 168MHz vs 84MHz，200kHz 时分辨率差一倍。
2. PSC 和 ARR 怎么算？→ `f=TIMclk/((PSC+1)(ARR+1))`；先算总 ticks，再拆。
3. 0% 和 100% 怎么保证？→ CCR=0 / CCR=ARR+1；ARR 留余量防止溢出。
4. 改频率为什么要产生更新事件？→ 预装载寄存器在更新事件才生效。
5. 捕获为什么用 32 位？→ 1Hz/84MHz=8400万，16 位溢出。
6. PWM 输入模式怎么测占空比？→ CH1 上升沿得周期，CH2 下降沿得高电平，从模式复位。
7. 200kHz 捕获中断会不会太多？→ 20 万次/秒，ISR 只存寄存器，主循环算。
8. 触摸为什么不能每轮扫？→ 40 次 AD+排序，毫秒级；会拖慢 UI。
9. 怎么做到不闪屏？→ 局部重绘、脏标记、固定宽度、背景色一致。
10. 相位怎么实现的？→ 按你选的方案解释，重点说"调相位时输出不停"。
11. 扫频为什么非阻塞？→ 触摸/PWM 不能停；状态机每次推进一步。
12. SPWM 50Hz 怎么保证？→ 20kHz 载波/400 点=50Hz，整数关系。
13. 优先级怎么排？→ 捕获最高、SPWM 次之、节拍最低；ISR 都短。
14. 栈只有 1KB 怎么办？→ 大数组全局，不 malloc，不递归。
15. 如果触摸坏了怎么办？→ 不能按 RESET；代码里不要依赖触摸才能启动 PWM；至少保留默认输出。

## 10. 一句话总结

**先把 PWM 和捕获用示波器/信号源调准，再把 UI 做成"局部刷新 + 非阻塞状态机"，最后按性价比加拓展。** 字库、触摸校准、SysTick、1KB 栈这四个坑，任何一个都能让演示当场翻车。
